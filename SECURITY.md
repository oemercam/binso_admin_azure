# Security Policy

## Binso One

Binso One is a software platform developed and operated by Binso GmbH, Switzerland.

We take the security of our applications, infrastructure, customer information and business data seriously.

This security policy explains how security vulnerabilities can be reported and how they are handled.

## Supported Versions

Security updates and vulnerability remediation are provided for the current production version of Binso One.

| Version | Supported |
| --- | --- |
| Current production release | Yes |
| Previous or discontinued releases | No |

Security fixes are evaluated based on their severity, exploitability and potential impact.

## Reporting a Vulnerability

If you discover a potential security vulnerability, please report it privately.

**Preferred reporting method:**

Use GitHub's private vulnerability reporting feature:

Repository → Security → Advisories → Report a vulnerability

Alternatively, contact:

**Binso GmbH**  
Email: oemer.cam@binso.ch  
Website: https://www.binso.ch

Please include, where possible:

- A description of the vulnerability
- The affected component or functionality
- Steps to reproduce the issue
- The potential security impact
- Relevant technical details or evidence

Do not include passwords, access tokens, private keys or unnecessary personal data in your report.

## Responsible Disclosure

Please do not publicly disclose a vulnerability before Binso GmbH has had a reasonable opportunity to investigate and address it.

Security testing must not disrupt production services, compromise accounts, access third-party data or cause data loss.

Any testing beyond systems and accounts you own or are explicitly authorized to test requires prior written authorization.

## Vulnerability Handling

Reported vulnerabilities are reviewed and assessed according to their severity and potential impact.

Our intended response targets are:

| Severity | Initial Response Target |
| --- | --- |
| Critical | Within 1 business day |
| High | Within 2 business days |
| Medium | Within 5 business days |
| Low | Within 10 business days |

These are targets rather than contractual guarantees.

Confirmed vulnerabilities are prioritized for remediation, testing and controlled deployment.

## Security Practices

Binso One follows security-oriented development and operational practices, including:

- Dependency and vulnerability monitoring
- Automated code quality and security checks
- Controlled production deployments
- Access control and authentication safeguards
- Protection of sensitive configuration and credentials
- Security review of significant application changes

Security measures are continuously reviewed and improved.
