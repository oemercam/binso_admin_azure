# V71.1 Multi-tenant type fix

This maintenance release keeps tenant ownership mandatory on persisted domain entities while making UI/store creation APIs tenant-safe.

## Corrections

- Creation inputs for contracts and orders no longer require callers to supply `organizationId`.
- Store creation methods for expenses, customer contacts, supplier invoices, time entries, time evidence and assignment rules accept tenant-neutral input and inject the active `currentOrganizationId` centrally.
- Registration API restores the missing `findActiveMembershipsForUser` import used by the GET endpoint.

This prevents UI callers from selecting or spoofing a tenant identifier while preserving mandatory `organizationId` on the persisted domain models.
