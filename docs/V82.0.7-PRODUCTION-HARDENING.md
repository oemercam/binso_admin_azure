# V82.0.7 – Production Hardening und Real-Customer-Acceptance

V82.0.7 schliesst die wichtigsten code-seitigen Produktionsrisiken nach dem Self-Service- und Billing-Rollout.

## Umgesetzt

- Billing-APIs liefern bei absichtlich fehlender Datenbank einen kontrollierten `503 service_unavailable` statt eines ungefangenen DB-Fehlers.
- Billing-Responses übernehmen eine stabile `X-Correlation-Id`, damit Client-, App-Service- und Provider-Fehler zusammengeführt werden können.
- Stripe Checkout und Billing Portal sind zusätzlich tenant-übergreifend über den bestehenden PostgreSQL-Rate-Limiter geschützt.
- Stripe-Webhook-Fehler geben keine internen Provider-/DB-Fehlermeldungen mehr an externe Aufrufer zurück; interne Details bleiben im Webhook-Inbox-Datensatz und in redigierten Server-Logs.
- `invoice.paid` und `invoice.payment_failed` sind explizit getrennt. Die endgültige Subscription-Lage wird weiterhin autoritativ direkt von Stripe geladen, damit Out-of-order-Events keinen neueren Zustand überschreiben.
- Server-Logging redigiert E-Mail-Adressen, Bearer-Tokens, Stripe-Schlüssel und sensitive Metadaten und versieht Einträge mit UTC-Zeitstempel.
- Trial-Lifecycle-Texte verwenden die zentrale `TRIAL_DAYS`-Konfiguration und können nicht mehr auf einen alten 14-Tage-Text zurückfallen.
- E2E-Acceptance deckt die öffentlichen Einstiegspunkte für Demo, 30-Tage-Trial und Direct Subscription sowie das kontrollierte Verhalten ohne E2E-Datenbank ab.
- `pnpm production-hardening:check` ist Bestandteil von `pnpm static:check`.
- `pnpm legacy-state:check` verhindert neue direkte Abhängigkeiten vom Übergangsmodell `tenant_business_state`; nur die fünf bekannten Repository-Grenzen bleiben vorläufig erlaubt.
- `pnpm production:acceptance` prüft nach einem Deploy die öffentlichen Produktionsrouten, Health, Registrierungseinstiege und Legal-Seiten gegen `APP_BASE_URL`.

## Absichtlich ausserhalb des Codes

Die folgenden Punkte benötigen weiterhin reale Provider-/Azure-Konfiguration und können nicht durch Source Code alleine abgeschlossen werden:

- Microsoft Entra External ID User Flow inklusive E-Mail-Code und Passwort-Reset.
- Stripe Live Keys, Prices, Webhook Endpoint und produktive Checkout-Abnahme.
- Microsoft Graph Mail-Credentials und produktives Senderpostfach.
- getrennte PostgreSQL-Rollen für Tenant- und Platform-Zugriff.
- Azure Monitor / Application Insights Alerts und Backup-/Restore-Drill.
