# V81.19.1 – Desktop navigation details compatibility

## Fix

The V81.19 desktop navigation used a non-existent React/TypeScript `defaultOpen` prop on the native `<details>` element.

V81.19.1 replaces it with the standards-compliant `open` attribute while preserving the intended behaviour: the `Mehr` section opens automatically when the current route belongs to a secondary or hidden navigation area, and otherwise remains user-toggleable.

## Validation

- `defaultOpen` removed from native `<details>`
- `open={moreActive || undefined}` used instead
- dedicated regression check added
